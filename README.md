# Haze Design System

Hazel Sellote's design language, extracted from a single stylesheet into a documented, reusable
system. Self-contained: its own tokens, its own components, its own brand assets, and no dependency
on any other project.

```
index.html             front door — forwards to the explorer
tailwind/              the design system
assets/                brand masters + generated UI sizes
tools/sync-assets.sh   regenerate derived brand sizes
```

Open `index.html`, or drop the folder on Netlify / Vercel / GitHub Pages. To work on the system:

```bash
cd tailwind && npm install && npm run serve
```

Then open `http://localhost:8788/index.html`. See [`tailwind/README.md`](tailwind/README.md) for the
build, the token architecture, the test story, and how to add a component.

## One system, not two

There used to be a second system in this folder — the same design language hand-written as
`tokens.css` + `system.css`, documented by `guide.html`, with no build step. It was folded into the
Tailwind system and removed. `tailwind/` is now the whole thing.

The merge was not a copy. The two had drifted into genuinely different systems:

|                | vanilla (retired)              | v1.0 (now)                          |
| -------------- | ------------------------------ | ----------------------------------- |
| accent         | `#84B067`                      | `#759D66`                           |
| primary text   | `#1B2415`                      | `#2B2F28`                           |
| type scale     | 9.5 / 12.5 / 13.5px            | 11 / 12 / 13 / 14px, leading paired |
| contrast       | one step measured 3.66:1       | every step solved, 4.5:1 floor      |
| themes         | light only                     | light + dark                        |
| tests          | none                           | per-component, run in the browser   |

v1.0's values won, because its ramps are generated by binary-searching OKLCH lightness against a
target ratio — a step that measures 3.66:1 cannot exist in them. The eight portfolio-only components
came across as stories: **Case Card**, **Post Card**, **Timeline**, **Detail List**, **Filter
Group**, **Link Row**, **Top Bar**, **Status Bar**. Everything else already had a counterpart.

## The retired values are still here

The live portfolio still ships the vanilla values, so they are kept as a record in the explorer's
**Reference** group rather than deleted:

- **Portfolio Original** — every retired token, its hex, its measured contrast, and the v1.0 role
  that replaces it. This is the map to use when the portfolio migrates.
- **Findings** — what surfaced during extraction, filterable by whether the merge closed it.

Four findings are still open, and all four are decisions about the **portfolio**, not about this
system:

- The custom cursor (`cursor: none !important` on `body *`) hides the pointer for anyone relying on
  a large or high-contrast system cursor.
- Case cards render in Arial on the live site — `.case` is a `<button>` and never set
  `font-family`. The Case Card story here is an `<a>` and carries a test that fails if the face
  falls back.
- Migrating will move line breaks slightly in dense copy, because the half-pixel type scale did not
  survive.
- The retired accent and faint-text steps are below AA and are still deployed.

## Brand assets

`assets/` holds the logo and favicon, synced from the portfolio by `tools/sync-assets.sh`. The
portfolio is the source of truth; derived UI sizes (`logo-128.png`, `logo-64.png`) are generated, not
hand-made, so they cannot drift. Use `logo-128.png` for any on-screen mark — `logo.jpg` is a 197KB,
2251px master and should never be loaded in a page.
